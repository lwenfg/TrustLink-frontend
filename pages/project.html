为无人系统载荷
建立可验证的安全链

TrustLink 面向无人机、无人车与地面机器人在开放无线、跨网远控和弱覆盖环境中的通信风险，将可信接入、身份认证、端到端密钥、载荷保护与路径隐私组织为一套可运行的安全通信系统。

PAYLOAD载荷保护

ROUTE路径最小知情

无人任务链路面临的是连续风险

安全问题并不止于“把数据加密”。设备身份、密钥材料、中继可见范围和覆盖缺口都会决定一次任务是否可信完成。

01 / ENTRY

未认证节点进入任务网

仅依赖网络可达无法证明设备运行状态或操作者身份，伪造端点可能参与后续会话。

02 / PAYLOAD

任务数据被窥探、篡改或重放

遥测位置、控制状态和视频载荷必须在传输前获得机密性、完整性和新鲜性保护。

03 / RELAY

中继转发暴露通信关系

跨基站或临时节点接力时，单个中继不应获得端点握手材料、业务明文或完整路径。

从地面控制台到无人端的完整系统架构

作品由控制展示、安全协议、路径服务和终端执行四部分组成。各模块既能独立运行，也能沿同一条任务链路协同完成接入、建链、传输和状态呈现。

地面站与无人设备保持端到端安全关系；需要跨节点传输时，目录服务、路径选择和逐跳加密共同建立受保护的承载电路。
CONTROL & VIEW

地面控制与展示

统一启动数传、图传和安全会话，持续呈现飞行遥测、视频画面、连接状态与中继路径。

SECURE SESSION

安全协议编排

按顺序完成接入证明、SRP-PAKE 身份认证、X3DH 密钥协商和应用载荷保护。

PATH SERVICE

目录与路径服务

维护可用节点信息，综合链路质量与节点状态选择路径，并为每一跳建立独立密钥。

EDGE & RELAY

无人端与中继执行

无人端采集遥测和视频，中继节点只解开本跳封装并转发，端到端载荷始终保持受保护状态。

一次安全通信任务如何运行

从操作者发起任务，到无人端数据回传，安全状态与业务数据沿同一条链路推进。

  1. 发起任务地面控制台选择直连、多基站或混合节点模式，并启动对应的数传与图传服务。
  2. 确认端点双方先校验接入证明，再通过口令认证建立只属于本次会话的身份上下文。
  3. 建立通道直连模式生成端到端密钥；多跳模式同时完成路径选择、逐跳协商与洋葱电路构建。
  4. 保护载荷遥测、控制和视频在发送前完成加密与完整性认证，序列号和时间戳用于识别重放。
  5. 呈现状态地面端解密有效数据，并将链路、遥测、图传和路径信息同步到 Web 控制台。
数据流

业务数据先保护，再进入网络

遥测、控制指令与视频帧在端点完成加密认证。无论中间经过固定基站、无人机还是地面机器人，中继看到的都只是受保护载荷。

密钥流

端到端密钥与逐跳密钥分工

端到端密钥负责保护真实业务内容，逐跳密钥负责隐藏路径上的转发关系；路径变化后重新绑定会话与电路上下文。

状态流

安全结果回到统一控制台

连接结果、协议阶段、遥测数据、视频状态和实际中继路径被集中展示，让操作者能直接检查当前链路是否可用、可信、连续。

按任务路径推进安全状态

系统先建立端点安全根，再根据网络条件选择直连、跨基站或混合接力的承载路径。

DIRECT LINK端点安全根

四阶段端到端协议

状态机依次完成可信接入证明校验、SRP-PAKE、SRP 保护的 X3DH 身份材料交换与应用层数据保护。任一阶段失败，临时状态和密钥材料会被清除。

接入证明 → SRP-PAKE → X3DH → SM4/SM3 + 序列号 + 时间戳
MULTI-HOP跨站路径隐私

先建电路，再承载握手

源端从目录筛选候选中继，经 VRF 生成可验证路径，与每一跳执行 ntor 风格 AKE，随后建立洋葱电路并在其中完成四阶段握手。

目录过滤 → VRF 选路 → 每跳 AKE → K_EO 预保护 → 洋葱转发
WEAK COVERAGE弱覆盖安全接力

基站与无人节点混合转发

固定基站、无人机和地面机器人共同组成候选图，路径评分综合可达性、带宽、RTT、丢包、电量、可信度与节点类型。

固定节点优先稳定；覆盖不足时由可信移动中继补位

协议图：内层端点保护，外层路径保护

两套协议按先后关系工作：多跳场景先完成可验证路径建链，再在受保护电路中传递端点认证与载荷数据。
